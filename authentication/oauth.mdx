---
title: OAuth
description: Sign people in with Coline and call the API on their behalf.
---

Use OAuth when your app acts for a person: it signs them in with their Coline account, they approve the scopes you ask for, and your app gets a token that can reach what that person can reach, limited to those scopes. Coline uses the OAuth 2.0 authorization code flow with PKCE.

If you're connecting an agent to the [MCP server](/api/mcp), you don't need any of this. MCP clients register and sign in on their own.

## Endpoints

| | URL |
| --- | --- |
| Authorization | `https://coline.app/api/v1/oauth/authorize` |
| Token | `https://coline.app/api/v1/oauth/token` |
| User info | `https://coline.app/api/v1/oauth/userinfo` |
| Metadata | `https://coline.app/.well-known/oauth-authorization-server` |

## Register a client

1. Open the [developer console](https://coline.app/developers/console), choose a workspace, and go to **OAuth clients**.
2. Name the client and add every redirect URL it will use. Redirects must match exactly.
3. Copy the client ID and client secret. The secret is shown once.

## 1. Send the person to authorize

Create a random `code_verifier`, derive `code_challenge = BASE64URL(SHA256(code_verifier))`, and redirect to:

```text
https://coline.app/api/v1/oauth/authorize
  ?response_type=code
  &client_id=YOUR_CLIENT_ID
  &redirect_uri=https://example.com/callback
  &scope=openid%20profile%20email%20workspace.read%20calendar.read
  &state=RANDOM_STATE
  &code_challenge=CODE_CHALLENGE
  &code_challenge_method=S256
```

| Parameter | |
| --- | --- |
| `response_type` | Always `code` |
| `client_id` | Your client ID |
| `redirect_uri` | One of the client's registered redirect URLs |
| `scope` | Space-separated [scopes](/authentication/scopes#oauth-scopes). Defaults to `openid profile email` |
| `state` | Returned unchanged; check it to prevent CSRF |
| `code_challenge` | 43 to 128 characters |
| `code_challenge_method` | Must be `S256` |

The person signs in if needed and sees a consent screen listing the scopes. When they approve, Coline redirects to `redirect_uri` with `code` and `state`. Codes expire after 10 minutes and work once.

## 2. Exchange the code

```bash
curl https://coline.app/api/v1/oauth/token \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -d grant_type=authorization_code \
  -d code=col_code_... \
  -d redirect_uri=https://example.com/callback \
  -d code_verifier=YOUR_CODE_VERIFIER
```

The token endpoint accepts form or JSON bodies. Send the client secret with HTTP Basic auth, or as `client_secret` in the body.

```json
{
  "access_token": "col_at_...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "refresh_token": "col_rt_...",
  "scope": "openid profile email workspace.read calendar.read"
}
```

Access tokens last one hour.

## 3. Call the API

```bash
curl "https://coline.app/api/v1/workspaces/acme/calendar/events?start=2026-10-12T00:00:00Z&end=2026-10-19T00:00:00Z" \
  -H "Authorization: Bearer col_at_..."
```

A token isn't tied to one workspace. Pass the workspace slug or ID in the path; the person must be a member of it. `GET /api/v1/me/workspaces` (scope `workspace.read`) lists their workspaces.

## Refresh

```bash
curl https://coline.app/api/v1/oauth/token \
  -u "YOUR_CLIENT_ID:YOUR_CLIENT_SECRET" \
  -d grant_type=refresh_token \
  -d refresh_token=col_rt_...
```

Each refresh returns a new access token and a new refresh token. The old refresh token stops working, so store the new one.

## User info

`GET /api/v1/oauth/userinfo` with the access token returns the signed-in person:

```json
{
  "sub": "user id",
  "email": "dana@example.com",
  "email_verified": true,
  "name": "Dana Kim",
  "given_name": "Dana",
  "family_name": "Kim",
  "picture": "https://...",
  "preferred_username": "dana"
}
```

## Errors

| Code | Meaning |
| --- | --- |
| `INVALID_CLIENT` | Unknown client, or the secret doesn't match |
| `INVALID_REDIRECT_URI` | The redirect URL isn't registered for the client |
| `INVALID_GRANT` | The code or refresh token is expired, used, or for another client or redirect |
| `INVALID_TOKEN` | The access token is unknown or expired; refresh it |
| `OAUTH_SCOPE_FORBIDDEN` | The token lacks a scope the route needs |
